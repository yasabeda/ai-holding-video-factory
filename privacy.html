Privacy Policy

This policy describes how AI Holding Video Factory ("the application") accesses, uses, stores and shares account data for its YouTube integration and its planned TikTok Sandbox integration (SYNORIA Video Factory). The application is operated by Synoria AI Corporation ("the operator").

1. YouTube API Services

The application uses YouTube API Services. By using the application you also agree to be bound by the YouTube Terms of Service. Google's handling of your data is described in the Google Privacy Policy.

2. Who uses the application

The application is a private tool. It is used only by the operator, with Google accounts, YouTube channels and TikTok accounts that the operator owns or is authorised to manage. It is not offered to the public.

3. Data the application accesses

With the consent given on the Google consent screen, the application accesses:

  • Account identity: the email address and Google account identifier of the account that signs in. Used only to confirm that the expected account and channel were connected.
  • Channel and video data: the channel identifier and title, and for videos the application uploaded: identifiers, titles, descriptions, visibility, scheduled publication time, processing status, thumbnails and captions.
  • YouTube Analytics data: report data for the connected channels, such as views, watch time, audience retention, subscribers gained and traffic sources.

The application uploads videos, thumbnails and captions and sets video details on the connected channels. It does not access channels that have not been connected.

4. How the data is used

  • To upload and schedule the operator's videos and confirm that the upload matches what was intended.
  • To avoid uploading the same video twice.
  • To understand how published videos performed and improve later videos.

The data is not used for advertising, is not sold, and is not used to train generalised artificial-intelligence models. Any automated analysis runs on the operator's own computer.

5. Storage and security

  • The application stores its account records and credentials on the operator's own computer. It has no externally hosted application backend or cloud database. A local loopback callback handles OAuth responses on that computer; the public GitHub Pages site does not receive those responses.
  • OAuth tokens are stored encrypted with the Windows Data Protection API under the operator's Windows account.
  • Channel identifiers, the account email, upload records and analytics reports are stored in local files and a local database on the same computer.

6. Sharing

Google user data is not shared with, transferred to or disclosed to any third party. Data moves only between the operator's computer and Google's servers.

7. Retention and deletion

  • OAuth tokens are kept while a channel stays connected and are replaced when the channel is re-authorised.
  • Upload records are kept as long as the operator runs the application, so that duplicate uploads can be prevented.
  • Analytics data is kept while the channel's authorisation remains valid and is refreshed from YouTube when new reports are fetched.
  • There is no automatic deletion schedule. Deletion is carried out manually by the operator. When a deletion request is received at the contact address below, the operator deletes the stored token and the stored data for that account within 7 calendar days. When access is revoked through Google, the operator deletes them within 30 calendar days.
  • Deleting data held by the application does not delete videos or data on YouTube itself.

8. Revoking access

You can revoke the application's access to your Google account at any time on the Google security settings page: https://security.google.com/settings/security/permissions. After revocation the application can no longer access the account.

9. Cookies and this website

The local application panel uses essential session and anti-forgery cookies for account authorization. A separate OAuth cookie expires after ten minutes. The public website is a static site hosted by GitHub Pages; it sets no cookies of its own and has no analytics or advertising. GitHub may log visitor IP addresses as described in GitHub's own privacy statement.

10. Google API Services User Data Policy

The application's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

11. Changes

If this policy changes, the new version will be published on this page with a new date.

12. Contact

Privacy questions, complaints and deletion requests: contact@synoriaai.com

13. TikTok account authorization and data

The TikTok integration is in Sandbox preparation and has not been enabled for real uploads. If enabled after configuration and operator approval, Login Kit will request user.info.basic, user.info.profile and video.upload. The application uses the account-specific identifier and username to verify the intended account, and keeps access and refresh tokens to perform only the granted operations. Each of the three accounts is connected separately. The application does not collect TikTok passwords, private messages, contact lists, or follower lists.

The application keeps the selected local video, its title, description and hashtags, the source channel, a content fingerprint, authorization and consent records, upload request identifiers, processing state and any publication link the operator records. With the operator's explicit consent to a particular video and account, it sends that video's MP4 to TikTok's creator inbox. Captions remain available locally for the creator to review and apply in TikTok. This integration does not request video.publish or automatically publish publicly.

The default Sandbox scope does not include video.list. The existing optional performance reader would require separate permission and consent before requesting the connected account's published-video link and view count. Missing access or metrics are recorded as unknown, not as zero. TikTok data is not sold, used for advertising, or used to train general-purpose AI models.

14. TikTok storage, sharing, retention and deletion

The client secret, account tokens and temporary authorization material are encrypted with Windows CurrentUser DPAPI in a dedicated app and Sandbox vault outside the source repository. They are used in memory for API requests and are excluded from logs, public pages and reports. The local database stores account bindings and upload/status records, not plaintext tokens. TikTok data is sent only to TikTok for the requested integration; Google account data is not sent to TikTok. TikTok handles received data under its Privacy Policy.

Tokens are kept while an account is connected, rotated on refresh and deleted locally when the operator disconnects. The application attempts to revoke the TikTok token on disconnect; an uncertain revocation requires the operator to check TikTok settings. Authorization attempts expire after ten minutes; consumed or denied attempts delete their verifier. Expired unused authorization material is purged locally. Upload records are retained while the operator runs the application to prevent duplicates; they are not evidence that a video was publicly posted.

The operator can revoke the app through TikTok's account settings for connected apps, disconnect it locally, and request deletion using contact@synoriaai.com. The operator handles deletion requests manually within the same seven-calendar-day period described above, including local tokens, identifiers, metrics and account records. Removing local records does not remove content already transferred to TikTok. Deletion of deduplication records requires checking posting history before reconnecting. There is no automatic TikTok data retention scheduler.
